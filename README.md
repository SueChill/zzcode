# zzcode

一个用 Python 编写的终端代码智能体，目前版本为 `0.1.0-dev`。

在终端里提出需求，模型可以读取项目、搜索代码、修改文件、运行命令，并根据工具结果继续处理。项目从简单的 API 对话逐步发展而来，用来实践智能体循环、工具注册、权限审批、会话保存和上下文管理。

## 快速开始

建议使用 Python 3.12 和支持颜色、鼠标事件的 Windows 终端。以下命令使用 **CMD** 语法。

在 zzcode 项目目录打开 CMD，首次安装依赖：

```cmd
py -3.12 -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
if not exist .env copy .env.example .env
```

编辑 zzcode 安装目录里的 `.env`，填写 API 密钥和账号可用的模型 ID：

```dotenv
DEEPSEEK_API_KEY=你的_API_Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=你的模型ID
```

启动：

```cmd
python main.py
```

输入普通文字后回车发送，输入 `exit` 退出。

### 在其他项目里使用

**启动命令执行时所在的目录，就是本次工作区。** 在目标项目目录打开 CMD，然后通过绝对路径运行 zzcode，无须切换到 zzcode 目录。

例如，本机已安装依赖的 Python 和 zzcode 位于以下位置时：

```cmd
"F:\Python\python.exe" "F:\1-todosomething\zzcode\main.py"
```

如果使用前面创建的虚拟环境，则改用虚拟环境的解释器：

```cmd
"F:\1-todosomething\zzcode\.venv\Scripts\python.exe" "F:\1-todosomething\zzcode\main.py"
```

程序仍从 **zzcode 安装目录**读取 `.env`、`SYSTEM.md` 和 `mcp.json`。工作区路径来自 `Path.cwd()`，启动后固定，不随模型调用变化。

## 终端操作

| 操作 | 效果 |
| --- | --- |
| 普通文字 + 回车 | 发送需求 |
| 输入 `/` | 显示本地命令候选，继续输入筛选 |
| 任务执行时按 `Ctrl+C` | 取消当前任务，回到输入处，保留已完成的修改 |
| 等待输入时连续按两次 `Ctrl+C`（2 秒内），或空输入时按 `Ctrl+D` | 退出程序；第一次 `Ctrl+C` 会清空输入并提示 |
| `Shift+Tab` | 循环只读 → 自动 → 完全访问；进入完全访问需确认 |
| 等待输入时按 `Ctrl+T` | 循环切换关闭思考和当前模型支持的力度，下一次请求生效 |
| 等待输入时按 `Alt+M` | 按配置顺序切换模型；少于两个完整配置时保持不变 |
| 审批时按 `y` / `n` | 允许或拒绝，也可用方向键、回车或鼠标选择 |
| 审批时按 `Tab` 或点击详情标题 | 展开、收起脚本、差异或完整参数 |
| 点击思考标题 | 在全屏终端界面中展开、收起该轮思考 |
| 点击长代码块标题 | 在全屏终端界面中展开、收起代码 |

思考内容使用灰色显示，正文开始后自动收起为可点击的「思考」标题；接口需要返回 `reasoning_content` 才有可展示的思考。非全屏模式仍提示用 `/reasoning` 查看最近一段。长代码默认收起，完整回复仍保存在历史中。

状态栏显示模型、上下文估算、思考力度、权限和任务状态，不再显示 MCP 与 Skill 数量；连接和技能详情仍可通过 `/mcp`、`/skills` 查询。

每次任务结束后会输出一行灰色摘要：状态、耗时、模型轮数、工具次数、改动文件和运行次数。摘要最多 140 字符，文件较多时只列前三个；纯聊天不输出摘要。

### 本地命令

本地查询和设置由程序直接处理。`/plan 需求`、`/execute` 和 `/continue` 会启动模型任务，并将用户输入的原始命令作为真实消息保存。

| 命令 | 用途 |
| --- | --- |
| `/help` | 在终端内查看按职责分组的命令和快捷键 |
| `/help 关键词` | 筛选命令，例如 `/help plan`、`/help 权限` |
| `/trace` | 查看最近任务摘要、最慢 5 轮及最多 5 条异常工具 |
| `/trace list` | 列出当前会话的任务和关键命令记录 |
| `/trace 编号前缀` | 查看指定追踪，前缀至少 4 位且必须唯一 |
| `/trace tree [编号前缀]` | 按需查看完整执行时间线 |
| `/trace report [编号前缀]` | 生成独立的离线 HTML 耗时报告 |
| `/undo` | 撤销最近一次产生文件变化的任务 |
| `/reasoning` | 查看最近一段完整思考 |
| `/thinking [off\|on\|auto\|力度]` | 查看或切换模型思考设置；auto 恢复接口默认 |
| `/model [next\|名称]` | 查看已配置模型、切换下一个或指定配置名称 |
| `/code` | 查看最近一段助手回复全文，包含完整代码 |
| `/usage` | 查看上下文估算、接口用量和输入输出预算 |
| `/compact` | 请求模型压缩较早历史，保留最近两轮原文 |
| `/permissions readOnly` | 切换到只读模式 |
| `/permissions auto` | 切换到自动模式 |
| `/permissions fullAccess` | 显式开启完全访问模式 |
| `/permissions` | 在只读和自动模式之间切换 |
| `/mcp` | 查看 MCP 连接、工具数量和失败原因 |
| `/skills` | 查看已发现的技能、安装位置和环境要求 |
| `/skills add "来源"` | 从本地目录或 GitHub 安装技能 |
| `/skills reload` | 重新扫描已安装技能 |
| `/project` | 查看项目配置 ZZCODE.md 及解析出的命令 |
| `/plan` | 进入规划模式，之后输入需求 |
| `/plan 需求` | 进入规划模式并直接开始分析需求 |
| `/plan show` | 查看已保存的目标、阶段、验收方式和进度 |
| `/plan off` | 回到普通对话，保留计划 |
| `/execute` | 确认执行已保存的计划，或继续未完成的计划 |
| `/continue` | 继续上次未完成的任务，例如达到轮数上限之后 |

## 本地追踪与耗时报告

默认记录任务的准备、快照、每轮模型请求、工具校验、审批、实际执行、结果保存和收尾。压缩、撤销、权限及计划变更等关键命令也单独留痕；帮助、用量、追踪查询不会制造新的任务记录。

一次任务执行对应一个 run，与 trace 一一对应；同一会话中的下一次请求产生新的 run，程序实例另有 process_id。每个 span 表示其中一个动作，有父编号、开始与结束事件、状态和耗时。位置如下：

```text
当前工作区\.zzcode\traces\会话编号\
  UTC时间-完整run_id.jsonl
```

JSONL 每行一条 JSON，带格式版本、递增序号和 UTC 时间；耗时使用单调计时器，避免系统时钟调整影响。每个任务独立文件，不会和其他进程共写同一个文件；首版有意不轮转或自动删除，32MB 是软告警阈值，达到后减少预览并丢弃可选事件，工具起止及收尾等结构记录继续写入。因此它不是文件大小上限，文件仍可能继续增长；默认预览关闭时可减少的内容更少。

任务结束后，在 zzcode 输入处查看：

```text
/trace
/trace list
/trace tree
/trace report
/trace report 3f2a9c1e
```

`/trace` 默认只给最近任务的摘要、最慢 5 轮及最多 5 条异常工具，避免长任务刷屏；`/trace tree [编号前缀]` 查看完整时间线。关键命令可以通过 `/trace list` 找到编号后指定查看。`/trace report` 在对应 JSONL 旁生成同名 HTML，并打印文件路径，用浏览器直接打开即可，无需服务、Docker 或联网资源。报告包括：

- 模型等待、工具执行、审批等待和其他开销四段耗时，父子动作不重复累加。
- 工具提出次数、实际执行、成功、拒绝、失败、超时、P50 / P95 与执行合计，以及最耗时操作。
- 停止原因详情、异常类型/HTTP 状态，以及“计划状态（模型记录）”中的阶段进度、受阻数与工具结果依据数。
- 每轮模型请求净耗时、真实生命周期、客户端处理耗时、首有效事件和首正文延迟、输入 / 输出及缓存 / 思考细分。
- 可按操作名和状态筛选、点击展开详情的执行瀑布图。

原始 `model_request.duration_ms` 保留真实起止跨度；`active_duration_ms` 扣除生成器 `yield` 交还客户端期间的 `client_consumer_ms`，耗时分类和排名使用净值，客户端处理计入其他开销。净值含网络、SDK 和解析，不是服务端纯推理时间；流读取受消费速度影响，无法还原服务端独立生成耗时。瀑布图条带仍按真实起止跨度绘制，右侧标注净耗时。旧记录不能事后拆出客户端处理，查询时会提示。

模型的首有效事件包含思考、正文或工具调用；首正文只记录实际正文，没有则为 null。两者均为从请求开始计算的实际延迟，首正文可能包含此前客户端处理。用量直接记录每次 API 返回的 usage，未收到时保留未知，不复用上一请求的统计。缓存与思考是输入、输出的细分，不重复计入总数。计划进度及依据数来自保存的计划状态，不能据此断言独立验收通过；相同调用与结果也可能来自合理重测。

工具内部取消时，执行状态记为“结果未知”，数据库补 `status: interrupted`、`result_confirmed: false`；未开始的工具在 trace 为“未执行”，数据库补 `status: cancelled`、`executed: false`。结果成功保存后发出按工具编号关联的回执，trace 详情显示数据库结果状态和是否已保存；两层状态名称对应各自含义。

模型也可以通过只读工具 `query_trace` 自行分析当前会话的记录，无需文件工具访问 `.zzcode`。支持任务列表、摘要、按轮耗时和错误统计、失败详情及按调用编号查询已保存结果；`run_limit` 可以按轮序号聚合最近多次任务。每轮返回样本任务数、工具调用数、失败数和失败率，失败率定义为 `(error + timeout) / tools`，拒绝、未执行和未知状态另列；没有工具调用时为 null。少量任务或不同阶段的相同轮序号不构成稳定规律。

默认排除当前请求，以及含追踪查询、其余仅为读取/诊断的分析任务；`include_diagnostics=true` 可包含此前诊断，`exclude_run_ids` 可按完整编号或唯一前缀显式排除任务，过滤后再选最近 N 次。指定 `run_id` 可直接查询单个任务。`limit` 在 list、rounds、errors 和 summary 的错误列表中表示条数；result 则使用独立的 `char_limit`（最多 2000）按字符分页，`offset` 随视图分别表示条目或字符偏移；不适用的限额参数会报错。工具不接受任意文件路径，结果详情做基础凭据遮盖，损坏记录、未知结果和旧计时口径明确标记；历史记录不能保证当前状态。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `TRACE_ENABLED` | `true` | `false` 关闭采集；也可使用启动参数 `--no-trace` |
| `TRACE_PREVIEW_CHARS` | `0` | 默认不保存参数和结果正文；显式开启时最多 2000 字符预览 |
| `TRACE_MAX_MB` | `32` | 单个任务文件的软告警阈值，保留结构与收尾记录 |

默认只保存元数据、内容长度、指纹和请求组成，不保存完整对话正文。显式开启预览后虽有常见凭据格式的基础遮盖，也应自行确认输出内容是否适合保存。追踪使用进程内后台队列写盘；队列满或写入失败只提示一次，不吞掉业务异常或取消。读取时识别序号缺口、损坏尾行及未闭合动作，报告会标出记录不完整。进程被强杀时可能丢失尾部，退出等待写盘也有时限。

## 规划与执行

短任务可以直接聊天。需要先讨论方案或分阶段推进的任务，可以这样开始：

```text
/plan 为项目添加登录功能，先阅读现有实现并给出方案
/plan show
/execute
```

规划阶段只向模型开放内置的阅读、目录、文本检索、联网搜索、时间、技能读取、计划/追踪只读查询工具，以及保存计划的 `update_plan`。文件新建、编辑、删除、命令运行和 MCP 工具会从可调用注册表中移除，即使当前权限为 `fullAccess` 也不能调用。计划先保存为草稿，用户输入 `/execute` 后才进入执行阶段；进入执行不会改变原有工具审批模式。

每份计划保存目标、版本、阶段和验收方式。执行时继续使用 ReAct 循环，模型用 `update_plan_step` 将当前阶段标为进行中、已完成或受阻；阶段内部仍自主选择工具。完成阶段必须引用该阶段开始后实际产生的读取、检索或运行结果，运行验证要求退出码为 0 且未超时。程序核对引用和运行状态，是否真正满足验收条件仍由模型判断，不能把存在依据等同于验收绝对正确。

普通聊天的工具结果直接保留原始正文。仅在执行计划时，对当前阶段可作为验证依据的结果添加一行“依据编号：xxx”，不再套 JSON 信封或重新序列化历史正文；数据库继续保存原始结果。模型可以复制该编号，也可以调用只读 `query_plan` 分页查询可用依据。命令候选同时提供命令摘要、工作目录和退出码，内联代码仅显示详情标记。依据校验错误返回错误码、可用编号及修复建议，写入/修改工具本身不能作为验证依据。

执行操作前必须先开始当前阶段。只有对应未完成阶段的依据错误会持久化待修复状态；参数写错、误更新已完成阶段等只报错，不锁其他阶段。待修复时暂停文件修改和普通执行，读取与诊断仍可继续；需要重跑验证时，给 `run_command` 或 `run_python` 指定 `revalidate=true`，实际命令必须逐次审批，完全访问模式也不能跳过。重验不会自动清除待修复状态，须引用真实结果正确完成阶段。重复标记进行中、先标受阻再重启阶段都不能消除已有依据问题。

连续 3 次同阶段校验失败会停止本轮自动重试，即使每次猜测的编号不同；结果先保存，再触发停止及未执行结果补齐。执行计划正常收尾却仍有未完成阶段时，trace 状态为 `plan_incomplete`（计划未完成）；取消、异常、轮数上限等原有停止状态保留，另附计划进度。

计划独立保存在会话数据库的 `plan_state` 中，并动态作为 `system` 资料参与请求与 token 预算。`/compact` 压缩聊天时不会移除或重写当前计划，恢复会话也会恢复模式和进度。取消、失败或达到轮数上限时，尚未完成的阶段保留，之后可以继续；恢复执行时仍需核实实际文件和运行状态。

全部阶段完成后自动回到普通对话。需要调整方案时重新输入 `/plan`，讨论修改后再次用 `/execute` 确认；修改阶段会清除受影响的后续进度。`/undo` 撤销文件后会清空现有计划的完成依据，并要求重新核实和确认。底部状态栏会标出“规划”或“执行计划”。

## 项目配置

在项目根目录创建可选的 `ZZCODE.md`，用普通 Markdown 写项目约定；`## 命令`（或 `## Commands`）小节里的列表会被解析成命令清单：

```markdown
# 项目说明

## 命令
- 测试：python -m unittest discover -s tests
- 构建：python -m build

## 约定
- 只改必要文件，不重排无关代码。
```

每次请求会注入项目说明和命令清单，最多 4000 字符，超出部分截断；内容只作为项目资料，不授予额外权限，也不能覆盖系统提示或用户目标。文件按 UTF-8 或 GBK 读取，修改后下一次请求生效。输入 `/project` 查看实际解析结果；格式不完整的行会被忽略，清单目前只提供给模型参考，不会自动执行。

## 配置

完整模板见 [.env.example](.env.example)。变量名沿用 `DEEPSEEK_` 前缀；模型调用使用 OpenAI 兼容的 Chat Completions 接口。其他服务可以通过密钥、基础地址和模型 ID 接入，但仍需支持项目使用的流式回复和工具调用字段。

| 配置项 | 说明 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 模型 API 密钥，启动聊天前需要填写 |
| `DEEPSEEK_BASE_URL` | API 基础地址，默认 `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | 实际请求的模型 ID |
| `MODEL_DISPLAY_NAME` | 可选，覆盖状态栏中的模型显示名 |
| `MODEL_CONTEXT_WINDOW` | 可选，模型上下文总容量，单位 token |
| `MODEL_MAX_OUTPUT_TOKENS` | 可选，单次回复的输出预算，包含思考 |
| `MODEL_THINKING` | auto 或留空跟随接口默认，enabled 开启，disabled 关闭 |
| `MODEL_REASONING_EFFORT` | 可选，DeepSeek 使用 low/high/max；千问 3.8 Flash/Max 使用 low/medium/xhigh |
| `MODEL_PROFILES` | 可选，按逗号列出模型配置名称及切换顺序；留空仅使用 default |
| `SHOW_REASONING` | 是否展示思考，默认 `true` |
| `TAVILY_API_KEY` | 可选，联网搜索密钥；未填时尝试客户端的免密钥模式，受可用额度限制 |
| `GITHUB_TOKEN` | GitHub MCP 和技能下载使用的令牌 |

显示名和上下文容量未指定时，会尝试从模型列表接口获取。查询不到容量时不会虚构上限，也不会启用基于该上限的拦截；可以手动填写 `MODEL_CONTEXT_WINDOW`。

思考控制当前适配 DeepSeek 官方接口及千问平台的 Qwen3.8 Flash/Max；千问平台部署的 DeepSeek V4 系列使用其接口格式。留空不会额外发送参数，未知接口不会猜测参数格式，非法档位会提示错误。Ctrl+T 和 `/thinking` 只修改本次运行的设置，重启重新读取配置，不写回 `.env` 或聊天消息。`SHOW_REASONING` 仅控制显示，关闭显示不会关闭模型思考；摘要压缩对已适配接口单独关闭思考，不改变普通请求的选择。

如需在默认模型与千问之间切换，在安装目录 `.env` 增加：

```dotenv
MODEL_PROFILES=default,qwen
MODEL_QWEN_API_KEY=你的千问密钥
MODEL_QWEN_BASE_URL=https://maas.qianwenaiapi.com/compatible-mode/v1
MODEL_QWEN_ID=qwen3.8-flash
MODEL_QWEN_DISPLAY_NAME=Qwen3.8-Flash
MODEL_QWEN_CONTEXT_WINDOW=1000000
```

`default` 继续使用原有 `DEEPSEEK_*`、`MODEL_*` 配置；其他名称使用 `MODEL_名称大写_*`，可另设 `MAX_OUTPUT_TOKENS`、`THINKING`、`REASONING_EFFORT`。按列表顺序选择第一个完整配置启动，缺少密钥、地址或模型 ID 的条目不加入列表；没有第二个完整配置时，Alt+M 不改变模型。`/model qwen` 选择指定配置，`/model next` 循环切换，`/model` 查看当前模型及可用列表；不从接口自动添加未配置模型。

模型切换仅在等待输入时操作，实际连接由主线程在下一次请求前更新。会话历史、工具、计划及累计用量保留，下一次请求继续携带当前会话上下文；名称、容量、密钥、地址和原生思考设置分别跟随模型。各模型在本次运行中选过的思考档位会保留，切回时恢复；新模型的上下文估算校准重新计算。切换不写回 `.env`，重启仍按配置顺序选择模型。

状态栏的上下文 token 为本地估算，输入和输出用量采用接口返回的统计。配置了容量时，请求前会预留输出预算和 5% 安全余量；超出预算会提示使用 `/compact`，不会自动压缩。已有终端环境变量优先于 `.env` 中的同名配置。

## 会话与撤销

每个工作区的对话保存在：

```text
当前工作区\.zzcode\sessions.sqlite3
```

用户消息、助手回复、工具调用和结果按顺序保存。正常结束或取消回复时保留已收到的内容；强制杀进程或断电可能丢失尚未保存的片段。

退出时打印会话编号。在**原工作区目录**中列出或恢复历史：

```cmd
"F:\Python\python.exe" "F:\1-todosomething\zzcode\main.py" --sessions
"F:\Python\python.exe" "F:\1-todosomething\zzcode\main.py" --resume 会话编号
```

`--resume` 支持完整编号或能唯一匹配的前缀；未指定时创建新会话。恢复时不再重复播放完整入场动画，改为显示会话编号、提问/消息数、主题和模型名，并回放最近 3 次提问：用户输入、助手正文、可点击展开的思考以及工具调用摘要。更早的记录仍保存在数据库中，不会因为只回放最近 3 次而删除。回放只读取历史，不重新请求模型；压缩后的摘要作为 `system` 历史资料参与后续请求，完整原始消息仍保留在数据库中。

`/undo` 使用内存快照，恢复最近一次产生变化的任务之前的文件状态，包括移除本轮新建文件。快照只在本次进程内有效，退出或恢复会话不会恢复撤销点；遇到后续手动修改会拒绝直接覆盖。命令造成的外部副作用不在文件撤销范围内。

## 工具与权限

内置工具包含：

- 文件操作：`read_file`、`write_file`、`edit_file`、`delete_file`。读取支持分段，自动识别 UTF-8（含 BOM）、GBK 和 UTF-16；覆盖或编辑已有文件前必须先读取，写回保持原编码、换行和 BOM；`edit_file` 默认要求旧文本唯一命中，可传 `replace_all` 全部替换。
- 项目检索：`list_files` 查看目录，`grep` 使用 Python 递归搜索文本，按字面匹配关键词。
- 执行验证：`run_python` 运行 Python 文件，`run_command` 运行程序及参数列表，返回输出、退出码和超时状态。
- 外部信息：`web_search` 联网搜索，`get_current_time` 获取本机时间。
- 状态查询：`query_workspace_state` 获取撤销、取消等关键事件记录。

运行命令没有交互输入，默认时限 30 秒，可设为 1～300 秒。模型可以运行测试，但目标项目需要的解释器、构建工具和依赖仍需实际安装；程序不会自动配置完整开发环境。

文件写入先在内存中生成完整变更并展示差异，审批通过后用同目录临时文件替换目标文件，失败时原文件保持不变。连续的文件变更（新建、编辑、删除）合并为一次审批和一份预览，其他工具仍逐个审批。

默认启动模式为 `readOnly`：

| 模式 | 读取 | 新建、编辑、删除工作区文件 | 运行命令及未预授权 MCP 工具 |
| --- | --- | --- | --- |
| `readOnly` | 直接执行 | 需要确认 | 需要确认 |
| `auto` | 直接执行 | 自动批准 | 需要确认 |
| `fullAccess` | 直接执行 | 自动批准 | 自动批准 |

也可在启动时指定，例如 `python main.py --permission-mode auto`。权限仅在本次运行有效；MCP 配置中的 `auto_approve` 是单独的预授权，在只读模式中也生效。

`Shift+Tab` 按只读 → 自动 → 完全访问 → 只读循环。进入完全访问前必须二次确认：全屏界面会显示警告并要求选择“确认切换”，默认停在“取消”；备用输入没有弹窗，需在 5 秒内再按一次 `Shift+Tab`。取消时保持原模式。`/permissions fullAccess` 和启动参数属于显式设置，不经过这次按键确认。

这些模式控制工具审批。内置文件工具限制在工作区内，并保护 `.env`、`.git`、`.zzcode` 等路径；`.env.example` 可以读取。**这不是操作系统沙箱，获准运行的命令具有当前系统用户的权限，可以访问文件工具边界之外的资源。**

每次真实用户请求最多调用模型 75 轮。到达 80% 时提示模型总结进度并收尾；撞到上限后返回输入处并提示 `/continue`，已完成的操作保留。同时检测重复调用、短周期循环、反复失败和被拒绝操作的原样重试。

## MCP

从 **zzcode 安装目录**的 `mcp.json` 读取配置，顶层字段为 `servers`，支持 `http` 和 `stdio`。模型仍通过统一的工具注册表选择和调用 MCP 工具。

当前随项目提供的 GitHub 配置使用 `GITHUB_TOKEN`，加载读取文件、搜索代码和搜索仓库三个工具，并明确预授权这些操作。在 `.env` 填写令牌，重启后用 `/mcp` 查看实际连接结果；启动时不刷连接提示。

MCP 在后台连接，状态栏不展示数量；用 `/mcp` 查看加载进度、服务与工具数量、失败原因。服务断开后工具总数保留，可用数量按实际连接状态计算。配置的令牌需要具有目标仓库的访问权限。

## Skill

技能统一安装到用户目录：

```text
%USERPROFILE%\.zzcode\skills\技能名\
├─ SKILL.md
├─ scripts\       （可选）
└─ references\    （可选）
```

这是不同工作区共用的位置，成功安装首个技能时创建。它与工作区内保存会话的 `.zzcode` 目录分别承担不同用途。

在 zzcode 输入处安装和使用：

```text
/skills add "D:\my-skills\demo-skill"
/skills add https://github.com/owner/repo/tree/main/skills/demo-skill
/skills
$demo-skill 帮我处理这个任务
```

本地来源需要包含 `SKILL.md`；GitHub 链接需要换成真实的技能目录。仓库根链接可以配合 `--ref 分支或提交` 和 `--path 仓库内目录`。技能名称来自 `SKILL.md` 的 YAML 元数据，使用小写字母、数字和单连字符，并与安装文件夹同名。

启动时发现技能，只将名称与描述交给模型；模型按任务需要调用 `load_skill` 获取正文，再用 `read_skill_file` 读取附带资料。显式输入 `$技能名` 时，程序会提前加载正文，作为本次任务的临时 `system` 参考内容，结束后清除。

安装复制技能和附带文件，记录来源，不执行脚本、不自动安装依赖，也不覆盖已有同名技能。脚本执行仍走运行工具和权限规则。程序只发现上述安装目录，不自动扫描当前项目、Codex 或其他程序的技能目录；手动放入合法技能后可用 `/skills reload` 刷新。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `main.py` | 启动、配置、输入循环和退出 |
| `project_config.py` | 读取项目根目录 ZZCODE.md 的说明和命令清单 |
| `tool_result.py` | 统一解析工具结果的状态、错误码和数据体 |
| `commands.py` | 本地命令分发与处理 |
| `agent.py` | 单次任务、模型循环、工具批次与异常收尾 |
| `planning.py` | 计划草稿、执行确认、阶段进度与验证依据 |
| `tracing.py` / `trace_report.py` | 本地事件采集、JSONL 读取、终端摘要与离线耗时报告 |
| `model.py` | API 调用、流式事件、消息历史、用量和压缩 |
| `tools.py` | 内置工具、注册表、参数检查和执行审批入口 |
| `terminal_ui.py` / `terminal_input.py` | 终端布局、输入补全、状态栏和审批交互 |
| `reply_display.py` / `details.py` | 回复、思考、工具状态和详情折叠 |
| `session_store.py` | SQLite 会话保存与恢复 |
| `snapshots.py` / `workspace_state.py` | 文件撤销和工作区事件记录 |
| `loop_guard.py` | 重复操作与失败检测 |
| `mcp_client.py` / `skills.py` | 外部工具接入与技能安装、加载 |
| `SYSTEM.md` | 智能体系统提示词 |
| `tests/` | 自动化测试，读法见 [tests/README.md](tests/README.md) |
| `tests/harness.py` | 测试公共脚手架：假模型、假终端与 `CliHarness` |

主链条：用户输入 → 模型请求 → 正文或工具调用 → 参数检查与审批 → 执行并保存结果 → 再次请求模型，直到本轮完成、取消或触发停止条件。

在 zzcode 目录运行测试：

```cmd
python -m unittest discover -s tests
```
